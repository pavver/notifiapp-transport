# Правила розробки NotifiApp Transport

Цей файл містить специфічні технічні правила та стандарти розробки для транспортного модуля NotifiApp Transport.
Загальні правила проекту дивіться в кореневому [RULES.md](../RULES.md).

## 1. Обробка помилок та паніки

- **Ніяких панік**: Суворо заборонено використовувати `.unwrap()`, `.expect()` або макрос `panic!()` у робочому коді.
- **Транспортні помилки**: Усі помилки повинні повертатись через тип [TransportError](src/error.rs).
- **Thiserror**: Для перетворення сторонніх помилок (наприклад, з `tungstenite` чи `snow`) використовуйте макроси `thiserror` у [error.rs](src/error.rs).

## 2. Асинхронний код та Tokio

- **CancellationToken**: Для безпечної зупинки фонових тасок (таких як цикл відправки чи пінгу) використовуйте `CancellationToken`.
- **Запобігання витокам пам'яті**: Завжди переконуйтесь, що всі фонові таски завершуються при руйнуванні ручки сесії або клієнта.
- **Блокуючі виклики**: Уникайте виконання тривалих або блокуючих синхронних операцій всередині асинхронного циклу без використання `tokio::task::spawn_blocking`.

## 3. Криптографія та Безпека

- **Очищення пам'яті**: Чутливі дані, такі як приватні ключі Noise, мають очищатись або видалятись із пам'яті якомога швидше після використання.
- **Шифрування за замовчуванням**: Будь-яка передача даних через WebSocket повинна відбуватись у зашифрованому вигляді через Noise сесію, якщо це не вимкнено явно у конфігурації.
- **Перевірка сертифікатів**: При підключенні до безпечних WebSocket (`wss://`) чи HTTPS серверів заборонено ігнорувати перевірку TLS-сертифікатів у продакшн-режимі.

## 4. Фічі та Залежності

- **Feature flags**: Пакет використовує фічі `ws`, `crypto` та `http`.
- **Мінімальні збірки**: Переконайтесь, що код успішно компілюється з будь-якою комбінацією увімкнених фіч (наприклад, лише `ws`, лише `http`, або `ws + crypto`).
- **Залежності**: Не додавайте важкі зовнішні залежності без погодження з командою.
